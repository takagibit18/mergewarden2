# LocAgent retrieval mechanism replication protocol

This is a preregistered PR-review retrieval experiment, not a reproduction of LocAgent paper results. The machine-readable protocol is `eval/locagent/protocol.json`; per-mechanism fidelity and limitations are in `eval/locagent/locagent-replication-fidelity.json`.

Baseline: `93d9da881bee6ea74b65fe261eb34151a79be844`. Golden r2 SHA-256: `07491d7803a4a25ded06e58d4acfae052e6ec2bd7575cff9867c9adf0c9f62d9`. Existing unstaged user documentation edits are excluded from executable fingerprinting. Official LocAgent reference: `4935b557326c154bad8e8dcf3747cc8d32d1f387`, specifically `plugins/location_tools/repo_ops/`, `dependency_graph/traverse_graph.py`, `util/runtime/content_tools.py`, and `util/runtime/function_calling.py`. Paper: <https://aclanthology.org/2025.acl-long.426/>.

Frozen layers: immutable snapshots, final-only submission/evidence ledger, coverage/delivery/cancellation, graph schema 2, resolver `python-scopes-2`, parser `web-tree-sitter-0.27.0/python-0.25.0-abi15`, HEAD graph, and all Golden r2 annotations/source/locks. Core wiring adds tool definitions only; T0 and G0 prompt/tool behavior stays unchanged. G1 is internal evaluation configuration, not a product mode.

T0 exposes four existing text/submission tools. G0 retains those plus unchanged exact graph_lookup and one-hop graph_neighbors. G1 exposes text/submission plus search_entity and traverse_graph. The latter reads the same verified SQLite graph and immutable sources in a cancellable worker. It creates no semantic edges. Retrieval state is outside the checkout. No reviewed Python, instructions, imports, scripts or plugins execute.

Search: unique exact ID/qualified entity, exact simple name, BM25 entity ID index, supplemental content BM25, finally fuzzy fallback. All candidate provenance stays visible. The official source keeps content search enabled after entity BM25 hits. The task-required fuzzy-last ordering differs from the reference. Sparse scoring follows bm25s Lucene; dependency-pinned reference vectors were generated using trusted libraries on inert strings, never reviewed Python.

Traversal follows the reference implementation's tree DFS (not the paper's BFS wording). upstream=incoming, downstream=outgoing; both splits only at a root. Node/relation filters prune traversal. Multiple roots, visited sets and explicit hops/nodes/bytes bound work and output. Search previews/full output remain explorationOnly. read_source is the RetrieveEntity adapter and is still mandatory for accepted evidence.

Stage A uses deterministic numerical/search/traversal/boundary tests. Stage B uses real Pi 0.84.1 with a scripted provider: Search → Traverse → read_source → submit, durable trace/report, bypass rejection and attribution. These are plumbing checks, never quality scores.

Stage C selects eight cases before new live outputs: cross-units and cross-key (cross-file contracts), multihop-retry and multihop-filter (chains), alias-normalize (alias), clean-guard/clean-key-migration/clean-conversion (three hard negatives). Existing r1 model results were already known; selection is not blind to that history. All r2 annotations remain frozen. This opportunity-enriched synthetic subset is not representative of general PRs.

Use BigModel GLM-5.3-Flash, MERGEWARDEN_API_KEY, timeout 120000 ms, 40 calls, registered maxTokens 8192, unchanged runtime reasoning defaults. Every arm uses the same materialized snapshot. Counterbalance T0/G0/G1, G0/G1/T0, G1/T0/G0 by case index. Save full effective runtime configuration, actual prompt hashes, implementation commit/fingerprint, protocol hash, host, order and start time. Only capability descriptions differ. Abort comparison on configuration/source drift. Keep every failure and partial in denominators; never replace runs. Output directories are exclusively claimed and outside checkout.

Primary observations: actual sparse usage, multihop usage, novel entities/paths, conversion to separate source reads, strict accepted evidence attribution, text/source calls and payload bytes. No model self-attribution. Prior read_diff/read_source/search_text/SearchEntity exposure removes novelty. Strict credit keeps the original resolved incoming caller/reference requirement, including resolved multihop path, temporal separation, exact accepted evidence and absence of competing discovery. Candidate edges never earn strict credit. Trace origin is derived separately from FindingCandidate. Unknown usage is null; character/4 appears only as rough_payload_estimate.

Stage D gate is frozen: all 24 attempts/freeze checks preserved, and either at least one strict G1 assisted finding or G1 novel-entity-to-source conversions exceed G0 with at least one conversion. Otherwise audit fidelity and stop if no implementation defect. No tuning prompts, cases or ranking to force a positive result. Full-corpus runs require a separate directory and saved positive gate. Quality requires explicit semantic prediction-to-Golden mappings; automated location matching is prohibited.

Run challenge: `node --experimental-strip-types eval/locagent/run.mjs --live --output OUTSIDE_CHECKOUT`. After reviewing mappings, derive metrics: `node --experimental-strip-types eval/locagent/analyze.mjs OUTSIDE_CHECKOUT`. Source extraction/graph/existing scorer remain frozen. G1 quality uses the unchanged per-arm scorer with a local label adapter; cost comes from native trace usage with null propagation.

Raw results and working reports belong outside this repository. This protocol lives here because the user explicitly requested an in-repository experiment specification. Results must distinguish measured deterministic/scripted/live evidence from design claims and cannot infer review benefit from successful graph construction.
